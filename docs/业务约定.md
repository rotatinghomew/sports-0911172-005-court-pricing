# 当前业务约定

slot 容量表示同一时段可预约单位数；member_reserved 是运营声明的会员保障容量。报价固定原价单，后续发布不改旧报价；reserve 即使无容量也留下候补尝试。tariffs 仍是人工价单；试价分析见 `docs/试价分析.md`，只做描述性证据整理与显式假设的方案，不自动改价。

## 数据与一致性

金额均为整数分；日期使用零补齐的日期或同一时区时间字符串，跨时区输入应由调用方先规范化。所有 ID 为业务编号。写入会增加修订并保留旧值，历史 `recorded_at` 是登记时间，不等于事实发生时间；不能据此推断未观测到的业务事实。

单次业务操作是一个事务，失败不留下中间结果；整份回放按顺序逐项执行，前一项成功不会因为后一项失败而撤销。现有重复编号拒绝语义及已完成状态的重试语义由业务操作维护。操作台 JSON 中 `results` 是操作结果，`state` 为当前业务记录；历史以 `Store.history` 查询，当前状态与历史不能混为一谈。

## 已有操作

- `capacity.open(id, count, member_reserved=0)`
- `capacity.block(id, count, reason)`
- `capacity.free(id)`
- `tariffs.propose(id, prices, reason)`
- `tariffs.publish(id)`
- `booking.quote(id, person, slot, expires, party, rain=False, event=False, member=False)`
- `booking.reserve(id, quote, at)`
- `booking.cancel(id)`
- `payments.capture(id, booking)`
- `payments.refund(id, cents)`
- `analysis.review(id, hours=None, slots=None, reason)`
- `analysis.draft(id, review, prices, member=None, assumptions=None, reason)`
- `analysis.submit(id, at=None)`
- `analysis.approve(id, tariff, at)`
- `analysis.reject(id, reason)`
- `analysis.reconcile(id, plan)`

分析类操作只读历史、另存评估与方案记录，不改动容量、价单、报价、预约或收款；方案的预测、实际生效价与到账收款分别记录，互不混用。

直接方法调用和本地操作台使用相同的业务服务。`data/demo.json` 展示一条正常经营路径，并不代表总体人群；它不适合用来宣称任何统计规律。扩展分析时应另外构造能辨别缺失、覆盖和信息时间的样本，不得把样本中的关联直接当成因果结论。
