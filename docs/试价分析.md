# 可审查试价分析

经营方提议统一涨价时，用本流程先出可审查的试价方案，送运营审批，不直接改价。分析只读历史记录，产出分三层留痕：**评估**（`review`，描述性证据）、**方案**（`plan`，含显式假设的预测）、**对账**（`recon`，对照生效价与实收）。预测收入不是到账收入，三者永不混写。

## 证据口径

- **一次选择**：同一 `party` 同一天的所有报价合并为一次选择。同组球友在互斥时段（同一天不同小时）持有多份报价、甚至占多个位，都只计一份需求；换时段（取消 A 改订 B）是转移，不算新增客流。容量与收款仍按实际预约记录，两个口径分列。
- **订满截断**：`reserved` 达到可用容量或存在候补的日期标记 `censored`，成交只是需求下限，候补与未成交报价不计为完整需求。
- **降雨与赛事混淆**：按小时汇总每个观测价位的需求信号，仅当两档价格存在天气赛事组合相同的日期时才给出对照（`supported`），且只作描述；组合不重叠时标记 `confounded_by`，不作因果断言。无报价日期的天气赛事记为未知，不当作无雨无赛事。
- **覆盖边界**：评估只列出历史观测到的价格×时段组合（`cells`）。未覆盖的组合不给出预测；要进入方案只能以分析人员署名的显式假设（`assumptions`）标明，方案中每条预测带 `basis: observed|assumption`。
- 时段编号需含 `日期-小时`（如 `2026-12-01-18`）才能归入小时组；无法解析的编号列入 `excluded_slots` 并说明。时段内价格发生变动的（报价口径不一致）列入 `mixed_price_slots`，不参与对照。

## 操作流程

1. `analysis.review(id, hours=[...], reason=...)`：生成证据评估，含各价位需求信号、截断标记、可比对照与混淆标记。同一状态重复评估结果一致，评估编号不可复用。
2. `analysis.draft(id, review, prices, member=..., assumptions=..., reason=...)`：分析人员圈定试价范围（`prices` 逐时段）与会员保障（`reserved_floor` 每时段会员保障容量下限，默认不低于现状；`accessible_floor` 会员可获得时段数下限，默认不低于基线）。方案联合比较三项指标的变化：净收益、候补未满足、会员可获得时段，基线与试价分列并给出差值。目标时段须落在评估范围内且有现行价。
3. `analysis.submit(id, at=...)`：送运营审批，方案进入 `submitted`。
4. `analysis.approve(id, tariff, at)`：批准前重新核对——目标时段的可用容量或会员保障容量自起草后有变化（包场、维护、会员保留）则拒绝批准，须重新评估。批准只生成**草稿价单**，并记录仍按原约定履行的有效报价与已确认预约数量；现行价此时不变。
5. `tariffs.publish(tariff)`：既有原子操作，整套价一次生效；中断重试不留半套价，重复发布保持同一价格版本。
6. `analysis.reconcile(id, plan)`：事后对账，分列预测净收益（分析假设）、实际生效价（`price` 记录及价单编号）、价格生效后登记的收款；其中按审批前旧报价履约的收款单独标为 `honored_old`，不计入新价收入。对账可重复执行刷新，只读不写收款记录。

`analysis.reject(id, reason)` 驳回送审方案；被驳回或已批准的方案不能再走批准。方案状态机：`draft → submitted → approved|rejected`。

## 限制

- 评估是描述性证据整理，不做统计建模，不自动给经营决策；合成样本的关联不能当因果结论。
- 容量与天气赛事取当前记录与报价标记；`recorded_at` 是登记时间，不能据此推断业务发生顺序，对账中的"之前/之后"按变更日志登记顺序划分。
- 历史未覆盖的价格与时段组合，即使方案批准上架，其预测仍属假设，应通过对账用实际收款核对。
